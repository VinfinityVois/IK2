# IK2 / Invoice Keeper — безопасное применение патча

## Что делает пакет

- Добавляет полноценный `.gitignore` для `.env`, SQLite-баз, Python-кэша и `.next`.
- Добавляет `backend/.env.example` без действующих секретов.
- Добавляет скрипт для пересоздания тестовых данных: он делает резервную копию SQLite, сохраняет существующие аккаунты, очищает платежи/периоды/журнал Telegram-уведомлений и создаёт разнообразный демонстрационный набор.

## Сначала обезопасьте GitHub

1. Если опубликованный `backend/.env` содержал действующий Telegram-токен, отзовите его у BotFather и создайте новый.
2. Смените `SECRET_KEY` и пароль администратора, если они были реальными. Смена `SECRET_KEY` аннулирует уже выданные JWT.
3. Удалите `backend/.env` и `backend/invoice_keeper.db` из отслеживаемых файлов Git. Одного удаления в новом коммите недостаточно: секреты остаются в истории. Если секреты были настоящими, сначала смените их, затем очистите историю по принятой в проекте процедуре.
4. Скопируйте `.env.example` в `backend/.env` и заполните локальными значениями.
5. Проверьте `git status` перед коммитом. Не добавляйте резервные копии БД.

## Заполнение базы демонстрационными данными

Из папки `invoice-keeper/backend`:

```bash
python scripts/reset_demo_data.py --dry-run
python scripts/reset_demo_data.py --confirm-reset
```

Скрипт намеренно требует `--confirm-reset`. Он сохраняет текущие аккаунты и их пароли, но удаляет все регулярные платежи, периоды оплат и записи журнала Telegram, а затем создаёт примерно 300 регулярных платежей, около 3 600 периодов оплат и до 600 синтетических записей журнала. Уведомления не отправляются в Telegram.

Новые демонстрационные аккаунты: `demo.user01` … `demo.user24`; пароль новых аккаунтов: `Demo-2026!ChangeMe`. Это тестовый пароль — не используйте его в рабочем развёртывании. Существующие аккаунты и их пароли скрипт не меняет.

Перед запуском убедитесь, что приложение остановлено и выбран именно тестовый файл БД. Автоматическая резервная копия создаётся рядом с SQLite-файлом, если используется локальная SQLite-БД. Для PostgreSQL скрипт не делает файловую резервную копию.

## Важно

Этот пакет не меняет исходники в GitHub автоматически и не реализует сам по себе refresh tokens, HttpOnly cookies, email verification, 2FA или rate limiting. Эти задачи требуют отдельного согласованного изменения API, frontend и конфигурации.
